1. 📖 Visão Geral do Projeto

Este projeto implementa um jogo multiplayer 2D de plataforma onde múltiplos jogadores podem se conectar a um servidor e jogar simultaneamente. O sistema utiliza a arquitetura cliente-servidor, onde um jogador hospeda o jogo (servidor/host) e outros jogadores se conectam como clientes.

🎯 Funcionalidades Principais:

  • Menu Principal: Interface para hospedar ou conectar-se a jogos
  • Sistema de Rede: Gerenciamento de conexões usando ENet (protocolo UDP confiável)
  • Spawn de Jogadores: Criação e sincronização de jogadores entre clientes
  • Movimentação Sincronizada: Sincronização de posição e movimento dos jogadores
  • Câmera Inteligente: Cada cliente segue apenas seu próprio jogador
  • Física de Plataforma: Sistema básico de pulo e movimento horizontal

🏗️ Arquitetura:

  • Servidor (Host): Gerencia o estado do jogo, cria e sincroniza jogadores
  • Clientes: Enviam inputs do jogador e recebem atualizações do estado do jogo
  • Autoridade: Cada jogador tem autoridade sobre seu próprio personagem

3. ⚙️ Configurações no Godot

1 Configurar o AutoLoad (NetworkManager)

O que é AutoLoad? AutoLoad permite que um script seja carregado automaticamente em todas as cenas, funcionando como um "singleton" global. Isso é perfeito para gerenciar conexões de rede que precisam existir em todo o jogo.

Como configurar:

  1. No Godot, vá em Project → Project Settings
  2. Na aba esquerda, clique em AutoLoad
  3. No campo Path, clique no ícone de pasta e selecione: res://scripts/NetworkManager.gd
  4. No campo Node Name, digite: NetworkManager
  5. Clique no botão Add à direita
  6. Clique em Close
💡 Por que isso é necessário?
O NetworkManager precisa estar disponível em todas as cenas (menu e jogo) para gerenciar conexões. Sem o AutoLoad, teríamos que recriar o NetworkManager em cada cena, o que causaria problemas de sincronização.

Verificação: Após configurar, você pode verificar no arquivo project.godot:

[autoload]

NetworkManager="*res://scripts/NetworkManager.gd"

2 Configurar a Cena Principal

O que é a cena principal? É a primeira cena que será carregada quando o jogo iniciar.

Como configurar:

  1. Vá em Project → Project Settings
  2. Na aba Application → Run
  3. No campo Main Scene, clique no ícone de pasta
  4. Selecione: res://scenes/MainMenu.tscn
  5. Clique em Close
✅ Verificação: No arquivo project.godot, você verá:
run/main_scene="res://scenes/MainMenu.tscn"

3 Configurar Inputs do Jogador

O que são inputs? São as ações que o jogador pode realizar (mover, pular, etc.).

Como configurar:

  1. Vá em Project → Project Settings
  2. Na aba Input Map
  3. Configure os seguintes inputs (clique em Add para cada um):
Nome do Input Tecla(s) Descrição
ui_left A ou Seta Esquerda Mover para a esquerda
ui_right D ou Seta Direita Mover para a direita
left A ou Seta Esquerda Alternativa para esquerda
right D ou Seta Direita Alternativa para direita
jump Espaço, W ou Seta Cima Pular
⚠️ Nota: O projeto já vem com esses inputs configurados. Você só precisa verificar se estão corretos.

Como criar no Godot:

  2. Adicione um nó Control como raiz (renomeie para MainMenu)

  6. Centralize o MainPanel (Anchors: Center)
  7. Adicione um VBoxContainer dentro do MainPanel
  8. Adicione os botões e labels dentro do VBoxContainer
  9. Repita o processo para o JoinPanel

Game (Node2D)

Como criar no Godot:

  1. Crie uma nova cena (Scene → New Scene)
  2. Adicione um nó Node2D como raiz (renomeie para Game)
  3. Adicione um Node como filho (renomeie para GameManager)
  4. Adicione o script scripts/GameManager.gd ao GameManager
  5. No GameManager, adicione um Node2D (renomeie para Players)
  6. Adicione outro Node2D (renomeie para SpawnPoints)
  7. Dentro de SpawnPoints, adicione vários Marker2D (SpawnPoint1, SpawnPoint2, etc.)
  8. Posicione os Marker2D onde os jogadores devem aparecer

  12. Adicione um Node2D chamado Level na raiz
  13. Dentro de Level, adicione StaticBody2D para o chão e plataformas

Os Marker2D definem onde os jogadores aparecem no jogo. É importante ter vários spawn points para evitar que todos os jogadores apareçam no mesmo lugar.

5. 💻 Explicação dos Scripts

1 NetworkManager.gd - Gerenciador de Rede

Função: Gerencia todas as conexões multiplayer do jogo. Este é um singleton (AutoLoad) que fica disponível em todas as cenas.

📡 Sinais (Signals):

  • player_connected(peer_id) - Emitido quando um jogador se conecta
  • player_disconnected(peer_id) - Emitido quando um jogador desconecta
  • connection_failed() - Emitido quando falha ao conectar
  • connection_succeeded() - Emitido quando conecta com sucesso

🔑 Constantes:

  • PORT = 7000 - Porta padrão do servidor
  • MAX_PLAYERS = 8 - Máximo de jogadores simultâneos

🔧 Funções Principais:

host_game(port) - Cria um servidor:

func host_game(port: int = PORT):
    var peer = ENetMultiplayerPeer.new()
    var error = peer.create_server(port, MAX_PLAYERS)
    if error != OK:
        return false
    multiplayer.multiplayer_peer = peer
    _add_player(1)  # Host sempre tem ID 1
    return true

join_game(ip, port) - Conecta a um servidor:

func join_game(ip: String, port: int = PORT):
    var peer = ENetMultiplayerPeer.new()
    var error = peer.create_client(ip, port)
    if error != OK:
        return false
    multiplayer.multiplayer_peer = peer
    return true
💡 Como funciona:
- ENetMultiplayerPeer: É o protocolo de rede usado (UDP confiável)
- multiplayer.multiplayer_peer: Define a conexão ativa
- Peer ID 1: Sempre é o servidor/host
- Peer IDs 2+: São os clientes conectados

🎯 Callbacks Automáticos:

O Godot chama automaticamente estas funções quando eventos de rede ocorrem:

  • _on_player_connected(peer_id) - Quando alguém conecta
  • _on_player_disconnected(peer_id) - Quando alguém desconecta
  • _on_connection_failed() - Quando falha ao conectar
  • _on_connection_succeeded() - Quando conecta com sucesso

2 GameManager.gd - Gerenciador do Jogo

Função: Controla o estado do jogo, spawna jogadores e gerencia sincronização.

📡 Sinais:

  • game_started() - Emitido quando o jogo inicia
  • game_ended() - Emitido quando o jogo termina

🔧 Variáveis Exportadas:

  • @export var player_scene: PackedScene - Cena do jogador (configurada no editor)

🎮 Funções Principais:

start_game() - Inicia o jogo (apenas servidor pode chamar):

func start_game():
    if not multiplayer.is_server():
        return  # Apenas servidor inicia
    
    game_started_flag = true
    _spawn_all_players()  # Spawna todos os jogadores
    _notify_game_started.rpc()  # Notifica clientes

_create_player_manually(peer_id, local_control) - Cria um jogador:

func _create_player_manually(peer_id: int, local_control: bool):
    var player_instance = player_scene.instantiate()
    player_instance.setup_for_network(peer_id, local_control)
    player_instance.position = _get_spawn_position()
    player_instance.name = "Player_" + str(peer_id)
    players_container.add_child(player_instance)
    
    # Notifica clientes sobre novo jogador
    _notify_player_spawned.rpc(peer_id, player_instance.position)

📡 RPCs (Remote Procedure Calls):

RPCs permitem que o servidor chame funções nos clientes e vice-versa:

  • @rpc("authority", "call_local", "reliable") - RPC do servidor, confiável
  • _notify_player_spawned(peer_id, position) - Notifica clientes sobre novo jogador
  • _notify_player_removed(peer_id) - Notifica clientes sobre jogador removido
⚠️ Importante sobre RPC:
- "authority": Apenas o servidor pode chamar
- "call_local": Executa localmente também
- "reliable": Garante entrega (mais lento)
- "unreliable": Não garante entrega (mais rápido, bom para posições)

3 Player.gd - Script do Jogador

Função: Controla movimento, física e sincronização de cada jogador.

🎮 Variáveis Exportadas:

  • @export var speed = 300.0 - Velocidade horizontal
  • @export var jump_velocity = -400.0 - Força do pulo
  • @export var player_color = Color.BLUE - Cor do jogador

🔑 Variáveis Importantes:

  • var player_id: int - ID único do jogador
  • var is_local_player = false - Se é controlado localmente

⚙️ Função setup_for_network():

Esta função é chamada quando o jogador é criado, configurando a autoridade:

func setup_for_network(id: int, local_control: bool):
    player_id = id
    is_local_player = local_control
    set_multiplayer_authority(id)  # Define quem controla este jogador
    
    # Verifica se é realmente o jogador local
    if multiplayer and multiplayer.has_multiplayer_peer():
        is_local_player = (id == multiplayer.get_unique_id())
💡 Autoridade (Authority):
Cada jogador tem autoridade sobre seu próprio personagem. Isso significa que apenas o cliente com o mesmo ID pode modificar esse jogador. Outros clientes apenas recebem atualizações de posição.

🏃 Função _physics_process():

Processa física e movimento (chamada 60 vezes por segundo):

func _physics_process(delta):
    # Apenas o jogador local processa input
    if not is_local_player:
        return
    
    # Processa movimento
    _handle_movement(delta)
    
    # Sincroniza posição se mudou
    if global_position.distance_to(old_position) > 1.0:
        _sync_position.rpc(global_position, velocity)

🎮 Função _handle_movement():

func _handle_movement(delta):
    # Gravidade
    if not is_on_floor():
        velocity.y += gravity * delta
    
    # Pulo
    if Input.is_action_just_pressed("jump") and is_on_floor():
        velocity.y = jump_velocity
    
    # Movimento horizontal
    var direction = Input.get_axis("ui_left", "ui_right")
    if direction != 0:
        velocity.x = direction * speed
    else:
        velocity.x = move_toward(velocity.x, 0, speed)
    
    # Aplica movimento
    move_and_slide()

📡 RPC de Sincronização:

@rpc("any_peer", "unreliable")
func _sync_position(pos: Vector2, vel: Vector2):
    # Apenas atualiza se NÃO for o jogador local
    if not is_local_player:
        global_position = pos
        velocity = vel
⚠️ Por que "unreliable"?
Para sincronização de posição, usamos "unreliable" porque: - É mais rápido (menos overhead) - Se um pacote for perdido, o próximo já terá a posição atualizada - Para posições, não é crítico perder um frame

5 CameraController.gd - Controle da Câmera

Função: Faz a câmera seguir suavemente o jogador local.

⚙️ Variáveis:

  • @export var follow_speed = 5.0 - Velocidade de seguimento
  • @export var camera_offset = Vector2(0, -50) - Offset da câmera
  • var target_player: Player - Jogador a ser seguido

🔍 Função _find_local_player_with_retry():

Tenta encontrar o jogador local várias vezes (porque pode levar tempo para spawnar):

func _find_local_player_with_retry():
    var max_attempts = 10
    var attempt = 0
    
    while attempt < max_attempts:
        target_player = game_manager.get_local_player()
        if target_player:
            global_position = target_player.global_position + camera_offset
            return
        await get_tree().create_timer(0.5).timeout
        attempt += 1

📹 Função _follow_player():

Faz a câmera seguir suavemente usando interpolação linear (lerp):

func _follow_player(delta):
    var target_position = target_player.global_position + camera_offset
    global_position = global_position.lerp(target_position, follow_speed * delta)
💡 Lerp (Interpolação Linear):
O lerp suaviza o movimento da câmera, criando um efeito de "seguir suavemente" em vez de "grudar" no jogador. Isso evita que a câmera trema.

6. 🌐 Como Funciona o Multiplayer

📊 Arquitetura Cliente-Servidor

🏠 Servidor (Host):
- ID sempre é 1
- Gerencia o estado do jogo
- Spawna jogadores
- Envia atualizações para clientes
- Tem autoridade sobre decisões importantes
👥 Clientes:
- IDs 2, 3, 4, etc.
- Enviam inputs do jogador
- Recebem atualizações do servidor
- Têm autoridade apenas sobre seu próprio jogador
- Recebem cópias dos outros jogadores

🔄 Fluxo de Conexão

  1. Host cria servidor: NetworkManager.host_game() cria um servidor ENet
  2. Cliente conecta: NetworkManager.join_game(ip, port) tenta conectar
  3. Handshake: ENet negocia a conexão
  4. Servidor adiciona jogador: _on_player_connected() é chamado
  5. Jogo inicia: GameManager spawna todos os jogadores
  6. Sincronização: Posições são sincronizadas via RPC

🎯 Sistema de Autoridade

Cada jogador tem autoridade sobre seu próprio personagem:

  • Jogador Local: Processa input, aplica física, envia posição via RPC
  • Jogadores Remotos: Apenas recebem atualizações de posição, não processam input
  • Servidor: Gerencia spawn, remoção e estado geral
⚠️ Regra de Ouro do Multiplayer:
"Cada cliente controla seu próprio jogador, mas o servidor é a fonte da verdade." Isso evita problemas como trapaça (cheating) e garante sincronização.

📡 Tipos de RPC

Tipo Uso Exemplo
@rpc("authority", "call_local", "reliable") Servidor → Todos (confiável) Notificar spawn de jogador
@rpc("any_peer", "unreliable") Qualquer → Todos (rápido) Sincronizar posição
@rpc("any_peer", "call_local", "reliable") Qualquer → Todos (confiável) Solicitar sincronização

🔄 Sincronização de Posição

O sistema de sincronização funciona assim:

  1. Jogador local processa input e move
  2. Se a posição mudou significativamente (>1 pixel), envia RPC
  3. Outros clientes recebem o RPC e atualizam a posição do jogador remoto
  4. O jogador local NÃO atualiza sua própria posição via RPC (evita conflito)

7. 🧪 Como Testar o Jogo

1 Teste Local (Mesma Máquina)

Método 1: Múltiplas Instâncias do Editor

  1. Abra o projeto no Godot
  2. Execute o jogo normalmente (F5 ou Play)
  3. Clique em "Hospedar Jogo" na primeira instância
  4. Abra uma segunda instância do Godot com o mesmo projeto
  5. Execute o jogo novamente (F5)
  6. Na segunda instância, clique em "Conectar ao Jogo"
  7. Digite 127.0.0.1 como IP e 7000 como porta
  8. Clique em "Conectar"

Método 2: Build Exportado

  1. Exporte o jogo (Project → Export)
  2. Execute o executável exportado duas vezes
  3. Um joga como host, outro como cliente
✅ Dica: Para testar com mais jogadores, abra mais instâncias do jogo. O servidor suporta até 8 jogadores simultâneos.

2 Teste em Rede Local (LAN)

  1. Certifique-se de que ambos os computadores estão na mesma rede
  2. No computador host, descubra o IP local (cmd → ipconfig no Windows)
  3. Execute o jogo no host e clique em "Hospedar Jogo"
  4. No computador cliente, execute o jogo
  5. Clique em "Conectar ao Jogo" e digite o IP do host
  6. Clique em "Conectar"
⚠️ Firewall:
Você pode precisar permitir o jogo no firewall do Windows para conexões de rede local funcionarem.
