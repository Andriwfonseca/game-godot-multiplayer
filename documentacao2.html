🌐 Low-Level vs High-Level Multiplayer no Godot

📋 Sobre esta documentação:
Esta documentação explica as diferenças entre os sistemas Low-Level e High-Level de multiplayer no Godot 4.5, mostrando como usar cada um, exemplos práticos, prós e contras.
⚠️ Sistema Atual do Projeto:
Este projeto está usando LOW-LEVEL (ENetMultiplayerPeer) com RPCs manuais. Você verá MultiplayerSpawner e MultiplayerSynchronizer no projeto, mas eles não estão sendo completamente utilizados (estão preparados para uso futuro).

1. 📖 Introdução: O que são Low-Level e High-Level?

🔧 Low-Level (Baixo Nível)

Low-Level refere-se ao uso direto de ENetMultiplayerPeer, que é a API fundamental de networking do Godot. Com Low-Level, você tem controle total sobre:

  • Criação de servidor e conexão de clientes
  • Gerenciamento manual de spawn de objetos
  • Sincronização manual via RPCs (Remote Procedure Calls)
  • Controle direto sobre autoridade (quem controla o quê)
  • Gerenciamento manual de estados de rede
✅ Vantagem Principal: Controle total e flexibilidade máxima para casos complexos.

🎯 High-Level (Alto Nível)

High-Level refere-se ao uso de SceneMultiplayer combinado com MultiplayerSpawner e MultiplayerSynchronizer. Com High-Level, o Godot automatiza muitas tarefas:

  • Spawn automático de objetos entre clientes
  • Sincronização automática de propriedades (@replicated)
  • Gerenciamento automático de autoridade baseado em nós
  • Menos código para escrever e manter
  • Mais fácil para iniciantes
💡 Nota Importante: High-Level ainda usa ENet por baixo dos panos, mas adiciona uma camada de abstração que facilita o desenvolvimento.

2. ⚖️ Comparação Geral

Característica Low-Level (ENet) High-Level (SceneMultiplayer)
Classe Base ENetMultiplayerPeer SceneMultiplayer
Spawn de Objetos Manual (você cria e gerencia) Automático (MultiplayerSpawner)
Sincronização Manual via RPCs Automática (MultiplayerSynchronizer)
Complexidade Alta (mais código) Baixa (menos código)
Controle Total (máxima flexibilidade) Limitado (facilita, mas restringe)
Performance Ótima (sem overhead extra) Boa (pequeno overhead de abstração)
Aprendizado Difícil (precisa entender networking) Fácil (mais intuitivo)
Casos de Uso Projetos complexos, jogos competitivos Prototipagem rápida, jogos casuais

3. 🔧 Sistema Low-Level (ENetMultiplayerPeer)

📦 O que é ENet?

ENet é uma biblioteca de networking UDP confiável. No Godot, ENetMultiplayerPeer é a implementação direta dessa biblioteca. Você trabalha diretamente com a API de baixo nível.

🏗️ Arquitetura Low-Level

  1. NetworkManager cria o servidor/cliente usando ENetMultiplayerPeer
  2. GameManager spawna jogadores manualmente quando detecta conexão
  3. Player envia posições via RPCs manuais
  4. Autoridade é gerenciada manualmente com set_multiplayer_authority()

💻 Como Usar Low-Level

1 Criar Servidor (Host)

# NetworkManager.gd
extends Node

const PORT = 7000
const MAX_PLAYERS = 8

func host_game():
    # Cria o peer usando ENet diretamente
    var peer = ENetMultiplayerPeer.new()
    var error = peer.create_server(PORT, MAX_PLAYERS)
    
    if error != OK:
        print("Erro ao criar servidor: ", error)
        return false
    
    # Define como multiplayer ativo
    multiplayer.multiplayer_peer = peer
    
    # Conecta sinais
    multiplayer.peer_connected.connect(_on_player_connected)
    multiplayer.peer_disconnected.connect(_on_player_disconnected)
    
    print("Servidor criado na porta: ", PORT)
    return true

func _on_player_connected(peer_id: int):
    print("Jogador conectado: ", peer_id)
    # Você precisa spawnar o jogador manualmente aqui

2 Conectar como Cliente

# NetworkManager.gd
func join_game(ip: String, port: int = PORT):
    # Cria o peer como cliente
    var peer = ENetMultiplayerPeer.new()
    var error = peer.create_client(ip, port)
    
    if error != OK:
        print("Erro ao conectar: ", error)
        return false
    
    # Define como multiplayer ativo
    multiplayer.multiplayer_peer = peer
    
    # Conecta sinais
    multiplayer.connected_to_server.connect(_on_connected_to_server)
    multiplayer.connection_failed.connect(_on_connection_failed)
    
    print("Conectando a ", ip, ":", port)
    return true

func _on_connected_to_server():
    print("Conectado ao servidor!")

func _on_connection_failed():
    print("Falha na conexão!")

3 Spawn Manual de Jogadores

# GameManager.gd
extends Node

@export var player_scene: PackedScene

func _on_player_connected(peer_id: int):
    # Você precisa criar o jogador manualmente
    if multiplayer.is_server():
        _spawn_player(peer_id)

func _spawn_player(peer_id: int):
    # Instancia o jogador
    var player = player_scene.instantiate()
    
    # Configura autoridade manualmente
    player.set_multiplayer_authority(peer_id)
    player.player_id = peer_id
    
    # Define se é local
    player.is_local = (peer_id == multiplayer.get_unique_id())
    
    # Adiciona à cena
    $Players.add_child(player, true)
    player.name = "Player_" + str(peer_id)
    
    # Notifica clientes via RPC
    _notify_player_spawned.rpc(peer_id, player.position)

@rpc("authority", "call_local", "reliable")
func _notify_player_spawned(peer_id: int, pos: Vector2):
    # Clientes também criam o jogador localmente
    if not multiplayer.is_server():
        _spawn_player_locally(peer_id, pos)

4 Sincronização Manual via RPC

# Player.gd
extends CharacterBody2D

var player_id: int
var is_local: bool

func _physics_process(delta):
    # Apenas jogador local processa input
    if not is_local:
        return
    
    # Processa movimento
    _handle_movement(delta)
    
    # Envia posição via RPC manual
    if position_changed:
        _sync_position.rpc(position, velocity)

@rpc("any_peer", "unreliable")
func _sync_position(pos: Vector2, vel: Vector2):
    # Apenas atualiza se não for o jogador local
    if not is_local:
        global_position = pos
        velocity = vel

🎯 Características do Low-Level

  • Controle Total: Você decide quando e como spawnar objetos
  • RPCs Manuais: Você define quais propriedades sincronizar e quando
  • Autoridade Manual: Você controla quem tem autoridade sobre cada objeto
  • Mais Código: Precisa escrever mais código para gerenciar tudo
  • Mais Flexível: Pode criar sistemas personalizados complexos
⚠️ Cuidados com Low-Level:
- Você é responsável por gerenciar todos os objetos na rede
- Precisa garantir que todos os clientes estejam sincronizados
- Erros podem causar dessincronização entre clientes
- Mais difícil de debugar

4. 🎯 Sistema High-Level (SceneMultiplayer)

📦 O que é SceneMultiplayer?

SceneMultiplayer é uma API de alto nível que usa ENet por baixo dos panos, mas adiciona abstrações como MultiplayerSpawner e MultiplayerSynchronizer para automatizar tarefas comuns de multiplayer.

🏗️ Arquitetura High-Level

  1. NetworkManager cria o servidor/cliente usando SceneMultiplayer
  2. MultiplayerSpawner spawna objetos automaticamente
  3. MultiplayerSynchronizer sincroniza propriedades automaticamente
  4. Autoridade é gerenciada automaticamente baseada no nó

💻 Como Usar High-Level

1 Criar Servidor (Host)

# NetworkManager.gd
extends Node

const PORT = 7000
const MAX_PLAYERS = 8

func host_game():
    # Cria o multiplayer usando SceneMultiplayer
    var peer = ENetMultiplayerPeer.new()
    var error = peer.create_server(PORT, MAX_PLAYERS)
    
    if error != OK:
        print("Erro ao criar servidor: ", error)
        return false
    
    # SceneMultiplayer gerencia tudo automaticamente
    multiplayer.multiplayer_peer = peer
    
    # Conecta sinais (opcional, para feedback)
    multiplayer.peer_connected.connect(_on_player_connected)
    
    print("Servidor criado na porta: ", PORT)
    return true

func _on_player_connected(peer_id: int):
    print("Jogador conectado: ", peer_id)
    # MultiplayerSpawner spawna automaticamente!
💡 Nota: High-Level ainda usa ENetMultiplayerPeer, mas trabalha com SceneMultiplayer que adiciona funcionalidades automáticas.

2 Configurar MultiplayerSpawner (No Editor)

No Editor do Godot:

  1. Selecione o nó GameManager na cena Game.tscn
  2. Adicione um nó MultiplayerSpawner como filho
  3. No Inspector do MultiplayerSpawner:
    • Spawn Path: ../Players (caminho para o container)
    • Spawnable Scenes: Clique em "Add" e selecione Player.tscn

Em Código (alternativa):

# GameManager.gd
@onready var multiplayer_spawner = $MultiplayerSpawner

func _ready():
    # Configura o spawner
    multiplayer_spawner.spawn_path = NodePath("../Players")
    
    # Adiciona Player.tscn à lista de spawnable
    var player_scene = preload("res://scenes/Player.tscn")
    # O spawner já está configurado no editor

3 Spawn Automático com MultiplayerSpawner

# GameManager.gd
extends Node

@export var player_scene: PackedScene
@onready var multiplayer_spawner = $MultiplayerSpawner
@onready var players_container = $Players

func _ready():
    # MultiplayerSpawner já está configurado no editor
    # Ele spawna automaticamente quando você chama spawn()

func _on_player_connected(peer_id: int):
    if multiplayer.is_server():
        # Spawn automático! O spawner cuida de tudo
        var player = player_scene.instantiate()
        player.name = "Player_" + str(peer_id)
        
        # O MultiplayerSpawner automaticamente:
        # - Sincroniza o spawn em todos os clientes
        # - Configura autoridade corretamente
        # - Gerencia remoção quando desconecta
        
        multiplayer_spawner.spawn(player)
        
        # Ou ainda mais simples - adicione à cena e o spawner detecta
        players_container.add_child(player, true)
✅ Vantagem: Com High-Level, você não precisa criar RPCs para sincronizar spawn. O MultiplayerSpawner faz isso automaticamente!

4 Sincronização Automática com MultiplayerSynchronizer

No Editor do Godot:

  1. Selecione o nó Player na cena Player.tscn
  2. Adicione um nó MultiplayerSynchronizer como filho
  3. No Inspector do MultiplayerSynchronizer:
    • Clique em "Replication Config" → "New SceneReplicationConfig"
    • Na aba "Properties", clique em "Add"
    • Selecione as propriedades para sincronizar (ex: position, velocity)

Em Código:

# Player.gd
extends CharacterBody2D

@export var speed = 300.0
@export var jump_velocity = -400.0

# MultiplayerSynchronizer sincroniza estas propriedades automaticamente
# Não precisa de RPCs manuais!

func _physics_process(delta):
    # Apenas processa se tiver autoridade
    if not multiplayer.is_authority_of_multiplayer_authority():
        return  # Outro cliente controla este jogador
    
    # Processa movimento normalmente
    _handle_movement(delta)
    
    # MultiplayerSynchronizer sincroniza position e velocity automaticamente!
    # Não precisa chamar RPCs!

func _handle_movement(delta):
    if not is_on_floor():
        velocity.y += gravity * delta
    
    if Input.is_action_just_pressed("jump") and is_on_floor():
        velocity.y = jump_velocity
    
    var direction = Input.get_axis("left", "right")
    if direction != 0:
        velocity.x = direction * speed
    else:
        velocity.x = move_toward(velocity.x, 0, speed)
    
    move_and_slide()
💡 Como funciona:
O MultiplayerSynchronizer monitora as propriedades selecionadas e as sincroniza automaticamente entre todos os clientes. Você não precisa escrever código de sincronização!

5 Configurar Autoridade no High-Level

# Player.gd
extends CharacterBody2D

func _ready():
    # Define autoridade baseado no player_id
    # No High-Level, isso é mais simples
    if multiplayer.has_multiplayer_peer():
        var my_id = multiplayer.get_unique_id()
        set_multiplayer_authority(my_id)
    
    # O MultiplayerSynchronizer respeita a autoridade automaticamente

func _physics_process(delta):
    # Verifica autoridade de forma simples
    if multiplayer.is_authority_of_multiplayer_authority():
        # Este cliente tem autoridade, processa input
        _handle_movement(delta)
    # Caso contrário, apenas recebe sincronizações

🎯 Características do High-Level

  • Spawn Automático: MultiplayerSpawner gerencia spawn/removal
  • Sincronização Automática: MultiplayerSynchronizer sincroniza propriedades
  • Menos Código: Muito menos código para escrever
  • Mais Fácil: Ideal para iniciantes
  • Menos Flexível: Pode ser limitante para casos complexos
✅ Vantagem do High-Level:
Você pode criar um jogo multiplayer funcional com muito menos código. O Godot cuida de sincronização, spawn e remoção automaticamente.

# NetworkManager.gd - LOW-LEVEL
extends Node

const PORT = 7000
const MAX_PLAYERS = 8

signal player_connected(peer_id)
signal player_disconnected(peer_id)

func host_game():
    # Cria servidor usando ENet diretamente
    var peer = ENetMultiplayerPeer.new()
    var error = peer.create_server(PORT, MAX_PLAYERS)
    
    if error != OK:
        return false
    
    multiplayer.multiplayer_peer = peer
    multiplayer.peer_connected.connect(_on_player_connected)
    multiplayer.peer_disconnected.connect(_on_player_disconnected)
    
    return true

func join_game(ip: String, port: int = PORT):
    # Conecta como cliente
    var peer = ENetMultiplayerPeer.new()
    var error = peer.create_client(ip, port)
    
    if error != OK:
        return false
    
    multiplayer.multiplayer_peer = peer
    return true

func _on_player_connected(peer_id: int):
    player_connected.emit(peer_id)

func _on_player_disconnected(peer_id: int):
    player_disconnected.emit(peer_id)

# GameManager.gd - LOW-LEVEL
extends Node

@export var player_scene: PackedScene
@onready var players_container = $Players

func _ready():
    NetworkManager.player_connected.connect(_on_player_connected)

func _create_player_manually(peer_id: int):
    var player = player_scene.instantiate()
    player.setup_for_network(peer_id, false)
    player.name = "Player_" + str(peer_id)
    players_container.add_child(player)
    
    # Notifica clientes via RPC manual
    _notify_player_spawned.rpc(peer_id, player.position)

@rpc("authority", "call_local", "reliable")
func _notify_player_spawned(peer_id: int, pos: Vector2):
    # Clientes também criam localmente
    if not multiplayer.is_server():
        var player = player_scene.instantiate()
        player.setup_for_network(peer_id, peer_id == multiplayer.get_unique_id())
        player.position = pos
        player.name = "Player_" + str(peer_id)
        players_container.add_child(player)

6. ✅❌ Prós e Contras

🔧 LOW-LEVEL (ENet)

✅ Prós:

  • Controle Total: Você decide exatamente o que acontece
  • Performance Máxima: Sem overhead de abstração
  • Flexibilidade: Pode criar sistemas personalizados
  • Debugging Direto: Você vê exatamente o que está sendo enviado
  • Casos Complexos: Ideal para jogos competitivos
  • Otimização Fina: Pode otimizar cada aspecto
  • Controle de Latência: Pode implementar técnicas avançadas

❌ Contras:

  • Mais Código: Precisa escrever muito mais
  • Mais Complexo: Requer conhecimento de networking
  • Mais Erros: Fácil esquecer sincronizar algo
  • Manutenção: Mais difícil de manter
  • Tempo: Leva mais tempo para implementar
  • Debugging Difícil: Problemas de sincronização são difíceis
  • Curva de Aprendizado: Mais difícil para iniciantes

🎯 HIGH-LEVEL (SceneMultiplayer)

✅ Prós:

  • Menos Código: Muito menos para escrever
  • Mais Fácil: Ideal para iniciantes
  • Rápido: Prototipagem rápida
  • Menos Erros: Godot cuida de sincronização
  • Manutenção: Mais fácil de manter
  • Automático: Spawn e sincronização automáticos
  • Bom para Começar: Perfeito para aprender

❌ Contras:

  • Menos Controle: Limitado pelo que Godot oferece
  • Performance: Pequeno overhead de abstração
  • Menos Flexível: Difícil criar sistemas personalizados
  • Black Box: Não vê exatamente o que acontece
  • Casos Complexos: Pode ser limitante
  • Debugging: Pode ser difícil entender problemas
  • Dependência: Depende das decisões da engine

7. 🎯 Quando Usar Cada Um?

🔧 Use LOW-LEVEL quando:

  • Jogo Competitivo: Precisa de controle total sobre latência
  • Otimização Extrema: Precisa de performance máxima
  • Sistema Personalizado: Precisa de mecânicas únicas de rede
  • Experiência Avançada: Você entende bem networking
  • Controle Fino: Precisa decidir exatamente quando sincronizar
  • Jogos Complexos: MMO, jogos com muitos objetos
  • Servidor Dedicado: Servidor separado do cliente

🎯 Use HIGH-LEVEL quando:

  • Iniciante: Está aprendendo multiplayer
  • Prototipagem: Quer testar ideias rapidamente
  • Jogo Casual: Jogos simples, plataforma, puzzle
  • Time Limitado: Precisa entregar rápido
  • Menos Jogadores: Poucos jogadores simultâneos
  • Casos Padrão: Casos que High-Level cobre bem
  • Facilidade: Prefere simplicidade sobre controle
💡 Dica: Muitos desenvolvedores começam com High-Level para prototipar e depois migram para Low-Level quando precisam de mais controle ou performance.

    is_local = local
    set_multiplayer_authority(id)

func _physics_process(delta):
    if not is_local:
        return

Depois (High-Level):

func _ready():
    if multiplayer.has_multiplayer_peer():
        set_multiplayer_authority(multiplayer.get_unique_id())

func _physics_process(delta):
    if not multiplayer.is_authority_of_multiplayer_authority():
        return
⚠️ Importante: Após migrar, teste cuidadosamente! High-Level funciona diferente de Low-Level em alguns aspectos. Sempre teste com múltiplos clientes.

🎓 Conclusão

📊 Resumo:
- Low-Level (ENet): Controle total, mais código, mais flexível, mais complexo
- High-Level (SceneMultiplayer): Automático, menos código, mais fácil, menos flexível
✅ Recomendação:
Para este projeto (jogo multiplayer 2D de plataforma), ambos funcionam bem. O projeto atual usa Low-Level, o que é bom para aprendizado e controle. Se quiser simplificar, pode migrar para High-Level usando MultiplayerSpawner e MultiplayerSynchronizer.
